# Row4 TurboQuant KV Metal experiment

## Scope and provenance

This experiment ports only the runtime TurboQuant KV-cache path to the Row4 llama.cpp tree.

- Row4 base: `llama.cpp master@67b70bd91b2f870d83d842d6d540b26fec25acad`
- TurboQuant source: `llama-cpp-turboquant@d14e36827586`
- Measurement build: `e970d352` before the final autosquash
- Device: Apple M5 Max
- Model: `qwen3-row4-v1.gguf`, Qwen3 Row4 8B, 36 layers, 32 Q heads, 8 KV heads, K/V head dimension 128

The port does not change GGUF. The three added types are runtime-only KV-cache types and use IDs that do not overlap the Row4/Fairy2i types:

| CLI name | GGML type | ID | Physical layout |
| --- | --- | ---: | ---: |
| `turbo2` | `GGML_TYPE_TURBO2_0` | 49 | 34 B / 128 = 2.125 bpv |
| `turbo3` | `GGML_TYPE_TURBO3_0` | 50 | 50 B / 128 = 3.125 bpv |
| `turbo4` | `GGML_TYPE_TURBO4_0` | 51 | 66 B / 128 = 4.125 bpv |

`turbo4` is fixed to the source repository's default 4-bit PolarQuant layout. The legacy 3-bit plus QJL layout is not included.

## Rotation and graph path

Each attention head is divided into independent 128-element groups. No dense 128 x 128 matrix is stored or multiplied. The implementation uses a signed Walsh-Hadamard butterfly:

```text
forward = D2 * H128 / sqrt(128) * D1
inverse = D1 * H128 / sqrt(128) * D2
```

The sign tables, centroid tables, norm correction, and operation order match the source commit. The Row4 model has a head dimension of 128, so no padding is needed.

The runtime data flow is:

```text
K Turbo: RoPE(Q) -> forward WHT -> Flash Attention against rotated K cache
V Turbo: Flash Attention returns a rotated value sum -> inverse WHT
Any Turbo pair: attention output -> BF16 -> F32 carrier -> Row4 output projection
```

BF16/BF16 continues to use the existing carrier SET_ROWS operation and Fairy2i/Row4 exact Flash Attention flags. Turbo configurations use ordinary SET_ROWS, an F16 mask, generic Flash Attention, and do not set `fairy2i_flash3`.

## Supported configurations

TurboQuant is an explicit Row4 Metal experiment. The default remains BF16/BF16.

| Configuration | Status |
| --- | --- |
| `bf16/bf16` | Existing exact path, unchanged |
| `turboN/turboM` | Supported for all nine combinations |
| `q8_0/turboN` | Supported |
| `turboN/q8_0` | Supported |
| `bf16/turboN`, `f16/turboN`, `q8_0/q8_0` | Rejected for Row4 |
| CPU or mixed CPU/Metal Turbo placement | Rejected |
| `offload_kqv=false` or Flash Attention off | Rejected |
| Head dimension not divisible by 128 | Rejected |

Tensor buffer overrides are rejected for Row4. When Flash Attention is `auto`, a Turbo pair changes it to enabled before graph construction.

Example:

```bash
build-rel-metal/bin/llama-cli \
    -m qwen3-row4-v1.gguf -ngl 99 -fa on \
    -ctk q8_0 -ctv turbo3
```

## Correctness tests

The Release Metal build ran the following nonzero test sets on the Apple M5 Max:

| Test | Cases | Result |
| --- | ---: | --- |
| Source byte oracle, WHT roundtrip, chunked dequant | 1 executable | Pass; WHT NMSE `1.31879107e-14` |
| `TURBO_WHT`, forward/inverse and roundtrip, D128/256/512 | 27 | Pass |
| `SET_ROWS_TURBO2/3/4`, I32/I64, small and large rows | 57 | Pass |
| Row4-shaped `FLASH_ATTN_EXT`, decode and prefill | 30 | Pass |

The FA set uses D128, 32 Q heads, 8 KV heads and covers all 9 Turbo/Turbo pairs plus both q8/Turbo directions for each Turbo type. No selected case printed `not supported`, `0/0`, or `FAIL`. FA uses the existing `5e-4` NMSE budget and SET_ROWS uses `0.05`.

The fixed quantization input is checked byte-for-byte against output generated by source commit `d14e36827586`. Whole-row and 256-element block-aligned chunk dequantization are bit-identical for all three types at lengths 128, 256, 384, 512, and 4096.

Seven invalid Row4 configurations were also run and returned a nonzero status: BF16/Turbo, F16/Turbo, q8/q8, CPU Turbo, mixed CPU/Metal Turbo, KQV offload disabled, and Flash Attention disabled.

## Long-context Metal optimization follow-up

The first port dequantized the same K/V data once for every GQA query head and used the generic quantized Flash Attention schedule. Profiling identified four avoidable costs:

- Turbo4 K/V dequantization was repeated for all four query heads that share one KV head.
- The decode path did not use the vector Flash Attention schedule.
- Turbo4 SET_ROWS packed a 128-element row serially.
- Long decode used too few partial workgroups.

The follow-up Metal path adds:

- A D128 GQA4 prefill kernel that dequantizes each Turbo4 K/V tile once and reuses it across four query heads.
- Half-precision QK, probability, and output matrices with about 23 KiB threadgroup memory.
- A fused decode chain for Q WHT, Turbo4/Turbo4 vector Flash Attention, inverse WHT, and BF16 output rounding.
- A GQA4 decode kernel with 64 partial workgroups at 32K and above.
- SIMD32 Turbo4 SET_ROWS packing.
- A configured-capacity route that dequantizes K/V once to F16 for prefill when the KV capacity is above 512 and below 32K. The graph cache makes the configured KV capacity the safe routing key; the current used length is not safe at graph-build time.

The specialized prefill path passed the existing `5e-4` NMSE budget at KV lengths 512 and 8192. The 8192 test uses 32 query tokens, 32 query heads, and 8 KV heads and ran as 1/1, not as a skipped case.

## K mean-centering experiment

`TURBO_K_MEAN_CENTER` is default-off and supports two experimental modes for Turbo4/Turbo4 with one fully offloaded Metal stream:

- `TURBO_K_MEAN_CENTER=1` implements the initial proposal exactly. It leaves the first 32 K vectors unchanged and subtracts their mean from later K vectors.
- `TURBO_K_MEAN_CENTER=2` subtracts the completed first-32 mean from all K vectors in the initial prefill batch and from every later K vector.

Mode 1 is not softmax invariant. It shifts only the logits for keys after position 31 relative to the warmup keys and causes severe quality loss. Mode 2 applies one common K translation to every key. For any query, this subtracts the same scalar from every exact attention logit, so softmax is unchanged before quantization. The residual K vectors have a smaller common component and quantize more accurately.

| Context | Turbo4 base KL | Turbo4 base top1 | Mode 1 KL | Mode 1 top1 | Mode 2 KL | Mode 2 top1 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1024 | 0.1552 | 77.3% | 2.1684 | 32.4% | 0.0355 | 91.0% |
| 4096 | 0.1546 | 81.6% | 2.1493 | 36.7% | 0.0418 | 89.8% |
| 8192 | 0.1343 | 81.6% | 2.2672 | 34.8% | 0.0389 | 89.5% |
| 16384 | 0.1292 | 82.4% | 2.3313 | 31.6% | 0.0382 | 88.7% |
| 32768 | 0.1189 | 83.2% | 2.4717 | 29.7% | 0.0505 | 85.9% |
| 65536 | 0.2491 | 75.4% | 2.7140 | 18.8% | 0.1108 | 82.4% |

Mode 1 should not be used. Mode 2 is materially better than uncentered symmetric Turbo4 across every tested context. It requires the initial prefill batch to contain all 32 warmup tokens. It does not retroactively rewrite warmup rows when the first 32 tokens arrive in smaller batches, and cache shifting or physical-row reuse is outside this experiment's scope.

## Known limits

- Metal only, full model offload only, D128 Turbo FA only.
- No padding path; the Row4 model already uses D128 heads.
- No F16/Turbo or BF16/Turbo mixed cache support.
- No CPU Row4 Turbo execution and no mixed CPU/Metal placement.
- No TQ3/TQ4 weight formats and no changes to GGUF serialization.
- No CUDA, HIP, Vulkan, or SYCL kernels.
- No TurboFlash, Sparse-V, profiling, layer-adaptive cache precision, InnerQ, or optional source-repository environment knobs.
- Turbo cache dequantization is fused into Metal Flash Attention. The follow-up also includes a Turbo4-to-F16 copy path used by the configured-capacity prefill route.

Raw commands, JSON, fixed generations, test logs, and perplexity logs are left untracked under `tmp/row4-turboquant-kv/`.
