# N-Gram 投机解码 Benchmark 数据集介绍

本 Benchmark 共包含 4 类任务、360 条样本，覆盖长文本摘要、检索增强问答、
基于上下文的问答以及短文本知识问答。不同任务具有不同的 prompt 长度和文本
重复特征，可用于观察 N-Gram 投机解码在多种生成场景下的表现。

| 数据集 | 任务类型 | 样本数 | 主要特点 |
| --- | --- | ---: | --- |
| Spec-Bench Summarization | 长文本摘要 | 80 | 输入通常是较长的新闻或文章，要求模型生成简短摘要 |
| Spec-Bench RAG | 检索增强问答 | 80 | prompt 包含多段检索文本和一个问题，输入较长且可能存在重复片段 |
| HAGRID | 基于上下文的问答 | 100 | 要求模型根据给定上下文回答，并使用编号引用支持答案 |
| TriviaQA | 短文本知识问答 | 100 | 通常只有一个简短问题，不提供检索上下文，主要依赖模型内部知识 |

## Spec-Bench Summarization

Summarization 数据集包含 80 条长文本摘要任务。每条样本由一篇较长的原始文本
和对应的参考摘要组成，prompt 使用 `Summarize:` 引导模型生成摘要。

该任务的输入较长，文章中经常出现重复的人名、地点、事件描述和固定表达，
因此可能为 N-Gram 历史匹配提供较多候选。它适合测试长 prompt 下的摘要生成
性能以及投机解码的命中和接受情况。

## Spec-Bench RAG

RAG 数据集包含 80 条检索增强问答任务。每条 prompt 通常由多段检索内容和
末尾的问题组成，数据中同时提供参考答案。

这类任务的 prompt 较长，并可能包含相似或重复的检索片段。模型需要从给定
材料中提取相关信息并组织答案。由于上下文中可能直接出现答案相关表达，RAG
是较适合观察 N-Gram 投机解码效果的任务之一。

## HAGRID

HAGRID 数据集包含 100 条基于上下文的问答样本，来自 `miracl/hagrid` 的
dev split。样本使用固定随机种子 42 抽取，并按源数据位置排序。

每条样本包含：

- 一个问题；
- 一段或多段带编号的上下文；
- 要求使用 `[1]`、`[2]` 等格式引用依据的回答指令；
- 长答案和短答案参考；
- 支持文档及来源信息。

该任务不仅要求答案正确，还要求回答能够被给定上下文支持。它适合观察模型在
有依据问答、引用生成和较长回答场景中的行为。

## TriviaQA

TriviaQA 数据集包含 100 条短文本知识问答样本，来自
`mandarjoshi/trivia_qa` 的 `unfiltered.nocontext` validation split，取源
数据中的前 100 条。

该任务不包含检索上下文，prompt 通常只有一个简短问题，例如人物、地点、年代
或常识问题。数据中提供标准答案及其别名。

由于输入短、文本重复较少，TriviaQA 通常不容易产生大量 N-Gram draft。它
可以作为低命中场景，用于观察 N-Gram 机制在缺少重复上下文时的额外开销。

## 数据格式

所有数据均使用 JSONL 格式，每行表示一条样本。评测脚本读取每条记录的
`turns[0]` 作为实际 prompt。数据中的参考答案可用于检查生成质量，但当前
性能评测脚本不会自动计算答案准确率。

四个数据文件分别为：

```text
spec_bench/summarization.jsonl
spec_bench/rag.jsonl
hagrid/hagrid_questions.jsonl
triviaqa/trivia_questions.jsonl
```

## 取样方式

评测脚本从每个选中数据文件的开头按顺序取样。默认从每个任务取前 20 条：

```text
4 个任务 × 20 条 = 80 条样本
```

可以使用以下参数调整每个任务的样本数：

```bash
--samples-per-task 5
```

此时会从每个任务分别取前 5 条，共运行 20 条样本。设为 0 时运行全部 360
条数据：

```bash
--samples-per-task 0
```

顺序取样可以保证不同后端使用完全相同的样本，便于复现实验和进行公平比较。
